# Техническое задание

## 1. Назначение документа

Документ фиксирует требования к вёрстке и реализации страницы интернет-магазина по предоставленному макету. Он используется как основа для разработки, проверки результата и определения готовности задания.

## 2. Общая идея проекта

Необходимо сверстать макет страницы интернет-магазина Banki.shop и реализовать предусмотренные пользовательские сценарии каталога товаров. Визуальная часть должна максимально соответствовать макету, а интерактивные состояния — корректно работать после перезагрузки страницы.

Источник дизайна: [макет Banki.shop в Figma](https://www.figma.com/file/6LxPDEsauEGanhR2nDW68X/Banki.shop?node-id=0%3A1).

## 3. Цель проекта

Получить готовое адаптивное веб-приложение интернет-магазина, визуально максимально близкое к макету и реализующее поиск, добавление позиций в корзину, сохранение состояния и просмотр подробной информации о товаре.

## 4. Scope проекта

### 4.1. Что входит в scope

- Вёрстка страницы интернет-магазина по макету Figma.
- Адаптивное отображение на экранах от 360 px.
- Поиск товаров по названиям.
- Добавление товара в корзину через кнопку «Купить».
- Визуальное отображение состояний покупки.
- Сохранение состояния товаров после перезагрузки страницы.
- Открытие модального окна с подробным описанием товара.
- Слайдер изображений товара в модальном окне.
- Настройка автоматизации сборки.
- Настройка CI/CD через GitHub Actions для публикации на GitHub Pages.
- Документирование запуска и сборки проекта в README.

### 4.2. Что не входит в scope

- Реализация серверной части, API, авторизации и оформления заказа, если это отдельно не появится в уточнённых требованиях.
- Реализация полноценной платёжной системы.
- Проработка дизайна страниц, отсутствующих в предоставленном макете.

### 4.3. Поздние и необязательные расширения

- Подключение реального API каталога и корзины.
- Дополнительные страницы и сценарии интернет-магазина.

## 5. Ближайшая цель реализации

Сверстать страницу по макету, подготовить каталог позиций и реализовать все обязательные интерактивные сценарии: поиск, покупку, сохранение состояния и модальное подробное описание товара.

## 6. Технологический стек

### 6.1. Обязательный стек

- Vue 2.7.
- Options API.
- TypeScript.
- Webpack.
- Pinia 2.x для управления состоянием корзины.
- Swiper в версии или с адаптером, совместимым с Vue 2.7.
- Node.js 16 для локальной разработки и CI.

### 6.2. Допустимые дополнительные зависимости

- Библиотеки иконок или прелоадеров — по необходимости, если они не ухудшают соответствие макету.

### 6.3. Ограничения и замечания по стеку

- Приложение должно запускаться и собираться на Node.js версии 16.
- Все версии зависимостей, чувствительные к версии Node.js или Vue, должны быть зафиксированы в `package.json` и lock-файле.
- Компоненты Vue должны использовать Options API; `setup()` и `<script setup>` не использовать.
- Pinia должна использоваться в совместимой с Vue 2.7 версии ветки 2.x.
- Конфигурация автоматизации должна быть рабочей и описанной в README.

## 7. Функциональные требования

1. **Строка поиска**

   - При вводе текста выполняется поиск по названиям позиций.
   - Карточки, не соответствующие поисковому запросу, должны исчезать или скрываться.

2. **Кнопка «Купить»**

   - При нажатии кнопка переходит в состояние «обрабатывается» на 2 секунды.
   - После состояния «обрабатывается» кнопка переходит в состояние «в корзине».
   - Состояния должны быть визуально различимы. Допустимо использовать preloader icon, purchase icon, checked icon и аналогичные элементы.
   - Дизайн состояний разработчик продумывает самостоятельно в рамках общего стиля макета.

3. **Сохранение состояния позиций**

   - После перезагрузки страницы должно сохраняться состояние каждой позиции: находится товар в корзине или нет.
   - Состояние хранится в Pinia и синхронизируется с `localStorage`; серверное хранение не требуется.

4. **Подробное описание позиции**

   - При клике на название или изображение товара открывается модальное окно с карточкой товара.
   - В карточке должны присутствовать краткое описание позиции и цена.
   - В карточке должен быть слайдер, содержащий от 2 до 4 изображений товара.
   - Для реализации слайдера использовать Swiper.
   - Дизайн модального окна разработчик продумывает самостоятельно с учётом визуального стиля основного макета.

5. **Адаптивность и совместимость**

   - Интерфейс должен корректно работать на ширине экрана от 360 px.
   - Вёрстка должна максимально соответствовать предоставленному макету; желательно добиться Pixel Perfect.
   - Результат должен корректно отображаться во всех популярных браузерах.

## 8. Архитектурные принципы

- Компонентная архитектура Vue 2.
- Использование Options API.
- TypeScript использовать для компонентов, моделей данных и store.
- Разделение отображения, состояния и данных товаров по отдельным ответственным компонентам/слоям.
- Общее состояние корзины централизовать в Pinia store.
- Состояния карточки товара должны быть явными и предсказуемыми: обычное, обработка покупки, товар в корзине.
- Данные товара должны содержать минимум название, краткое описание, цену и 2–4 изображения.
- Реализация должна быть пригодна для расширения каталога без копирования разметки карточек.

## 9. Требования к структуре проекта

Рекомендуемая структура, допускающая адаптацию к выбранной конфигурации сборки:

```text
src/
  assets/
  components/
    ProductCard/
    ProductModal/
    ProductSlider/
    SearchBar/
  data/
  stores/
    cart.ts
  views/
  App.vue
  main.ts
public/
.github/
  workflows/
    deploy.yml
README.md
package.json
```

Фактическая структура может отличаться, если сохраняется разделение компонентов и ответственности. Конфигурация сборки должна быть размещена в корне проекта.

## 10. Требования к стилям и UI-архитектуре

- Стили должны обеспечивать максимальное визуальное соответствие макету Figma.
- Необходимо предусмотреть адаптивные состояния для ширины от 360 px.
- Интерактивные состояния кнопок покупки должны иметь отдельное визуальное оформление.
- Модальное окно должно визуально отличаться от основного контента и поддерживать закрытие предусмотренным интерфейсом способом.
- Слайдер должен позволять просматривать все изображения товара.
- Для слайдера использовать Swiper; его стили и навигация должны быть адаптированы под макет.
- Способ организации CSS/SCSS не задан и может быть выбран при реализации.

## 11. Требования к модели данных

Для каждой позиции каталога требуется предусмотреть:

- уникальный идентификатор;
- название;
- краткое описание;
- цену;
- массив из 2–4 изображений;
- признак нахождения в корзине;
- состояние операции покупки.

Допустимые состояния операции покупки: `idle`, `processing`, `inCart` либо эквивалентная модель.

## 12. Источник данных и хранение

- Источник каталога — предоставленный макет Figma.
- Названия, изображения и остальные доступные данные товаров необходимо перенести из Figma в локальные данные проекта.
- Реальные API и серверное хранилище не требуются в рамках текущего ТЗ.
- Состояние товара в корзине должно храниться в Pinia и сохраняться в `localStorage` между перезагрузками страницы.
- Состав каталога и изображения должны быть подготовлены как локальные ассеты проекта.

## 13. Этапы реализации

1. Изучить макет Figma и определить структуру страницы, карточки и модального окна.
2. Подготовить Vue 2.7-проект на TypeScript и конфигурацию Webpack, совместимую с Node.js 16.
3. Подготовить модель и локальный набор данных товаров.
4. Реализовать базовую адаптивную вёрстку страницы и карточек.
5. Реализовать поиск по названиям.
6. Реализовать состояния кнопки покупки и переход в корзину с задержкой 2 секунды.
7. Добавить локальное сохранение состояния корзины.
8. Реализовать модальное окно, описание, цену и слайдер из 2–4 изображений на Swiper.
9. Проверить соответствие макету, адаптивность и работу в популярных браузерах.
10. Описать команды установки, запуска и сборки в README.
11. Настроить GitHub Actions для сборки и публикации приложения на GitHub Pages.

## 14. Критерии готовности

- Страница сверстана и визуально максимально соответствует макету Figma.
- Проект запускается и собирается на Node.js 16.
- Проект использует Vue 2.7, Options API, TypeScript, Webpack и Pinia 2.x.
- Поиск фильтрует позиции по названию.
- Кнопка покупки последовательно показывает обработку в течение 2 секунд, затем состояние «в корзине».
- Состояние корзины сохраняется после перезагрузки.
- Клик по названию или изображению открывает модальное окно.
- В модальном окне отображаются краткое описание, цена и слайдер с 2–4 изображениями.
- Интерфейс корректно отображается от 360 px и в популярных браузерах.
- README содержит инструкции по установке, запуску и сборке.
- GitHub Actions автоматически собирает и публикует приложение на GitHub Pages.
- Код приложения размещён в GitHub.

## 15. Спорные места и риски

- Нужно аккуратно перенести из Figma доступные названия, изображения и данные товаров; часть данных, отсутствующая в макете, может потребовать ручного заполнения.
- Не определены точные правила закрытия модального окна и поведение слайдера; требуется выбрать стандартное понятное поведение.
- Не указан конкретный набор поддерживаемых браузеров; ориентиром считаются актуальные популярные браузеры.
- Pixel Perfect зависит от доступности всех шрифтов, изображений и параметров макета из Figma.
- Не определено, нужно ли скрывать или полностью удалять карточки при отсутствии совпадений поиска; допустимы оба варианта.
- Не определены тексты и иконки промежуточных состояний кнопки; их внешний вид необходимо разработать самостоятельно.
- Vue 2 и Node.js 16 устарели, поэтому версии Pinia, Swiper, Webpack и инструментов CI нужно зафиксировать и проверять совместно.
- Актуальные версии Swiper могут быть ориентированы на Vue 3; необходимо выбрать Vue 2.7-совместимую версию или адаптер до установки зависимостей.
